# v0.1.24 Release And GitHub Visuals Design

## Goal

Publish Agent Tmux Web v0.1.24 with current professional GitHub visuals, verified public Android artifacts, and release notes covering the Raw-first workbench redesign and edge-to-edge output update.

## Release Scope

- Set the package version to `0.1.24`.
- Set Android `versionName` to `0.1.24` and `versionCode` to `25`.
- Replace the stale Unreleased changelog content with a `0.1.24` entry dated `2026-07-21`.
- Publish a GitHub release tagged `v0.1.24` from the merged release commit.
- Attach the generic public sideload APK and generic Play Store AAB.
- Attach the reviewed 30 fps MP4 showcase.
- Include SHA-256 checksums for every release artifact.

## Visual Direction

The visual system is product-led and restrained. Actual Agent Tmux UI is captured from the built-in fake demo mode. Image generation is used only for a subtle abstract dark technical backdrop with no text, logos, terminals, people, devices, or invented UI. The real logo, typography, and product captures are composited locally over that backdrop.

The GitHub project will publish only these reviewed assets:

- `docs/assets/agent-tmux-web-hero.png`: 1600x900 release hero with a real desktop Raw capture.
- `docs/assets/desktop-raw.png`: authentic 1440x900 desktop Raw workbench.
- `docs/assets/mobile-raw.png`: authentic 390x844 mobile Raw view.
- `docs/assets/mobile-gui.png`: authentic 390x844 mobile GUI view.
- `docs/assets/mobile-focus.png`: authentic 390x844 mobile Focus view.
- `docs/assets/modes-overview.png`: composed Raw, GUI, and Focus comparison.
- `docs/assets/agent-tmux-web-showcase-poster.png`: static video poster.
- `docs/assets/agent-tmux-web-showcase.mp4`: professional animated showcase.

No GIF is published as the primary animation. README uses the hero and static product images, then links the poster to the MP4 to avoid low-frame-rate autoplay and oversized repository media.

## Motion Direction

- Render at 1920x1080, 30 fps, H.264, `yuv420p`, CRF 18, and no audio.
- Keep total duration between 12 and 18 seconds.
- Use eased opacity and position transitions, restrained 1-2% scale movement, and clean crossfades.
- Hold each product state long enough to read.
- Do not use fake device spins, cursor theatrics, glitch effects, aggressive zooms, jump cuts, or invented notifications.
- Use actual captured UI at native aspect ratios without stretching.

## Capture And Composition

`scripts/capture-marketing.mjs` remains the single generator. It starts a loopback-only production server, uses `?demo=1`, captures only fake repository demo data, and shuts the server down in `finally`. It generates raw product captures first, then builds the hero, modes overview, poster, and MP4 from those captures plus the generated abstract backdrop.

The image-generation request uses a fixed prompt and seed for a dark, low-contrast, abstract terminal-infrastructure texture. The generated image must be inspected before composition and rejected if it contains text, logos, people, devices, terminal windows, or recognizable product UI. If the endpoint fails or violates those constraints, asset generation stops; it does not silently substitute a cheesy or inaccurate visual.

## Privacy And Authenticity

- Never capture the private service, private concept URL, auth token, personal path, live tmux content, upload, or server address.
- Only loopback demo mode and fixed fake paths such as `/workspace/project` may appear.
- Scan generated images, video frames, metadata, repository diffs, APK, and AAB for private values before publication.
- Do not commit intermediate frames, temporary HTML, image-generation responses, or browser traces.
- Do not embed a private server URL or token in Android artifacts.

- New product features or native Android behavior.
- Private APK generation or distribution.
- AI-generated product UI, people, phones, laptops, terminal text, logos, or app screenshots.
- Play Store submission; the release includes the verified generic AAB only.
